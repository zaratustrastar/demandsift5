# T01 — timing and accepted-configuration instrumentation

Implemented locally on August 31, 2026. No production deployment or paid provider run. This ticket adds measurement, not a claimed speed improvement.

## Changes

- `scan-observability.ts`: versioned JSON trace events with execution/job/scan correlation, independent span IDs, monotonic durations and wall-clock milestones. A closed attribute vocabulary drops arbitrary prompt/query/body/email/header/error payloads. Throwing, rejecting or hung collectors cannot fail or delay work.
- `scan-workflow.ts`: stage, crawl, AI operation, discovery/enrichment, checkpoint, result-ready and failure observations. All budget/model/provider construction now uses the accepted scan's environment instead of re-reading mutable process settings mid-run. No budget, model, prompt, filtering or scheduling defaults changed in T01.
- `scan-configuration.ts` and additive optional scan fields: persist the allowlisted environment (including absent settings), configuration hash, effective workflow/provider limits and server timestamps before external work. Credentials are obtained at execution time, never copied into state. Endpoint text is represented only by hashes; a changed route fails closed rather than silently mixing routes during recovery. Credential rotation is allowed, but a run cannot silently acquire/lose AI or direct fallback.
- AI provider: attempt start/end events, including failed requests without usage; separate primary/direct-fallback route labels and Surplus/direct/compatible endpoint categories; usage, structured-recovery and coverage diagnostics. Diagnostic collectors are nonblocking and nonfatal. Existing usage-accounting callbacks retain their contract.
- Harshmaur provider: separate actor-run spans with counts and returned run identifiers, plus effective configuration receipts. Actor build stays explicitly unverified.
- Worker/executor: job ID propagation, queue eligibility wait versus total job age, monotonic execution duration. Worker heartbeat is not reported as completed provider work. Failed-job logs now use a safe category instead of raw upstream error text.

New traces intentionally do not contain source text. This is not a claim that every pre-existing log elsewhere in the application is sanitized. Full traces are server logs, not additional copies of unbounded events inside the scan's JSON record. Public presenter/status responses do not expose the internal configuration receipt.

## Verification

- 16 new tests cover independent overlapping spans, clock reversal, payload redaction, broken/hung collectors, preserved provider results, settings persistence/resume, credential/route handling, unsuccessful AI requests, concurrent AI requests, unchanged provider defaults, failed actor runs and workflow wiring.
- Focused regression group: **106 passed**.
- Full suite: **527 total, 525 passed, 1 failed, 1 skipped**. The sole failure remains the documented stale landing-page heading assertion from T00; it was not changed. The skip remains the opt-in live Apify probe.
- Node 24.19.0 application build, TypeScript no-emit check and lint pass; lint retains the same three pre-existing font warnings.
- Some existing source-shape assertions were updated to follow `observedCrawl` and explicit environment arguments. Their original four-page/security, context-only, review-depth, zero-audit and worker-resume assertions remain. Runtime provider tests exercise the actual modules with synthetic responses.

## Limits and recovery

`defaultsVersion` identifies the cb24c44 default semantics. Future tickets changing defaults must explicitly handle existing receipts instead of silently claiming their old effective receipt describes new behavior. Pricing/account identities are not scan execution controls and are not frozen by this ticket. API keys are not persisted. Endpoint changes require restoring the accepted route or starting a new scan; no secret-bearing URL is stored to reconstruct an old endpoint.

No database migration or deployment configuration is needed for these optional JSON fields. Existing records obtain a receipt on their next accepted execution. Upcoming overlap, compact-output and partial-result flags remain false. Revert this ticket's commit to remove the wiring; old readers ignore its optional persisted fields. The previous checkpoint is `checkpoint/t00-baseline`.
