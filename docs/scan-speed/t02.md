# T02 — review depth independent of thread fetching

Implemented and verified locally August 31, 2026. This is a quality correction; it can increase AI work/cost and is not a speed claim. Production is unchanged.

## Behavior

- Deep review now uses `REDDIT_DEEP_QUALIFICATION_BUDGET`, otherwise an explicit legacy `REDDIT_ENRICHMENT_BUDGET`, otherwise **8**. Comment-fetch settings never determine deep-review count.
- Valid explicit review budgets are integers 1–20. Invalid values fail visibly before provider work. A new explicit setting below an existing explicit legacy budget is rejected rather than silently shrinking review depth. The environment example leaves the new override commented out to preserve existing higher settings.
- Selected candidates omitted by a provider's smaller fetch cap are retained as discovery-only records for AI qualification. No comments, surrounding context or thread-verification flag are invented.
- Only an actual provider configuration declaring thread fetching disabled relaxes the existing publishing context bar; an absent/unrelated global Apify variable no longer relaxes other providers. Invalid Harshmaur fetch limits fail visibly instead of falling back silently to disabled verification.
- Fetching intentionally off reports zero fetch failures and zero additional threads verified. The existing full-context target and `coverageLimited` diagnostic remain honest. With fetching enabled, unsuccessful verification still prevents public promotion under the existing context gates, and incomplete context cannot be described as a definitive zero.
- T01 receipts explicitly migrate to `quality-depth-v2`, recording the previous configuration ID and calculating depth from **saved** settings. Their prior effective receipt is rebuilt; today's environment overrides do not rewrite an interrupted scan's accepted scope.
