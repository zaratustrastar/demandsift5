# T06 — durable analysis and explicit approval

Implemented locally August 31, 2026. Production and paid services were not touched.

## Behavior

- Initial analysis uses a deduplicated `scan.analyze` job in the existing PostgreSQL queue. Acceptance persists the job and scan receipt in one transaction. Website analysis still uses the same four-page policy and full business-understanding path; context input remains supported.
- A separate `scan.run` job requires approval of the exact completed profile, search overrides and competitor evidence. Its version hash survives JSONB object-key reordering. Stale approvals conflict; refresh and duplicate clicks do not silently start new discovery.
- The worker handles both job types with T05 attempt/execution fencing. A durable `analysisCompletedAt` marker distinguishes finished analysis from a profile checkpoint saved midway through it, and stays valid if an approved Reddit scan starts before the analysis worker's final poll.
- Public create calls now perform analysis only unless explicitly creating for review first. Clients must submit the reviewed version to `/run`; this is an intentional API contract change. Existing internal monitoring workflows retain their previous path. The local/mock synchronous path remains available and does not claim durable execution.
- The browser saves the scan ID in its URL, polls accepted work, and restores the correct review/scan screen. Context-only scans restore their input mode and can render a report without an invented website hostname.

## Verification

- Actual PostgreSQL repository plus actual workflow with synthetic IO: concurrent analyze acceptance deduplicates; analysis finishes without Reddit; stale approval rolls back job creation; concurrent valid approvals create one run job; approved discovery reuses the analyzed profile.
- Built API: incomplete/stale approval rejection, edited review versions, context restore, report mapper, repeated run and cross-workspace denial.
- Internal executor: wrong attempt rejected; a midway profile is not completion; completed analysis is not restarted while the full scan is queued or failed.
- Browser with isolated PostgreSQL and mock Reddit: close the tab after analysis acceptance, start the worker, restart the web process, reopen the saved URL, review the completed profile, approve, and reach the completed report. Exactly one analysis job and one run job succeeded with one attempt each. No real credentials or paid APIs were used.
- Full suite: 589 tests, 587 pass, the one previously documented obsolete landing-heading assertion fails, and one paid live probe is skipped. Build, TypeScript and lint pass (three existing font warnings).

No migration is required: lifecycle/approval fields are additive JSONB. Deploy web and worker together after draining old executors, as required by T05. This ticket improves durability and user flow; it does not claim a measured scan-time reduction.
