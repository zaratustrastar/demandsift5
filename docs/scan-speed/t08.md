# T08 — honest waiting, recovery and return UX

Implemented locally August 31, 2026. No production changes or paid scans.

## User flow

- Waiting screens show accepted/queued work separately from active stages and scheduled retries. Search, successful relevance checks, unresolved checks, deep reviews, actual thread verification and saved reply counts use T07 data. Concurrent stages can display together; there is no percentage bar or equal-duration stage assumption.
- Removed the half-minute/minute-or-two claims and the landing page's unsupported two-minute result promise. No new ETA is invented.
- Elapsed time uses saved analysis/run intervals and excludes the intervening review pause. Worker heartbeat and last saved progress have separate labels. A delayed heartbeat is a recovery notice, not proof that the scan failed.
- Safe-to-close wording appears only after durable acceptance. A native button copies a private return link; workspace authorization still applies. Context input no longer claims that website pages are being read.
- Completed analysis goes directly through optional competitors to profile review. Removed the obsolete 140-second refinement poll and its timed shortcut to an incomplete profile. Old incomplete/fast profiles ask for a new reviewed scan rather than silently approving a thinner one.
- Reload restores the saved phase without creating or starting another Reddit scan. A late initial restore cannot replace a newly submitted scan. A failed connection keeps saved progress visible; access/acceptance problems are distinguished from a server-reported failed scan.

## Polling

`lib/client/scan-polling.ts` provides one active request per loop, 3-second visible polling, 30-second hidden polling, immediate focus/online refresh, bounded transient-error backoff, a 30-second request timeout and cancellation on cleanup. A focus event during a request queues a refresh instead of overlapping it. Status and final report fetches are sequential. Failed status requests never infer authority to create a new scan; an ambiguous analysis acceptance is reconciled through status rather than repeated paid execution.

`lib/client/scan-progress-view.ts` holds testable elapsed-time and counter-copy rules. The existing visual design is retained with accessible stage-list labels, polite connection notices, a keyboard-native return-link control, wrapping small-screen styles and reduced-motion rules. Desktop DOM layout was checked for horizontal overflow; physical/mobile-device and assistive-technology QA remain part of T19's release checklist.

## Verification

- Eight behavior tests cover cadence/visibility, repeated focus during an outstanding request, backoff and recovery, cancellation/timeouts, terminal states, proxy/rate-limit/invalid JSON handling, persisted elapsed intervals, and exact progress copy. Source guards protect restoration, approval-only starts and no invented timing.
- Browser + isolated PostgreSQL: accepted queued analysis with worker paused; worker completion → competitors → review without another refinement wait; approval → one queued run. A guarded synthetic progress overlay showed 6/9 searches, 175 reviews, an individual retry and two concurrent stages. Its one-minute analysis plus six-minute scan excluded the 30-minute review gap, and survived reload without resetting.
- Stopping the local web process left the saved screen visible with a reconnect notice. Restarting it recovered automatically. Reload preserved counters/elapsed time; the desktop layout had no horizontal overflow. The overlay was then restored to its original queued record, the mock worker completed normally, and the report opened. Exactly one analysis job and one run job succeeded, each on one attempt.
- `tests/helpers/seed-browser-scan-progress.mjs` makes that overlay reproducible. It accepts only a named loopback test database and a marked synthetic scan with no active execution, saves/restores the original record, and makes no provider calls. Never use it against a real workspace.
- Final full suite: **606 total, 604 pass, 1 known obsolete landing-heading failure, 1 skipped paid probe**. Build, TypeScript, lint and whitespace checks pass; three existing font warnings remain.

These are user-flow and status-overhead improvements, not evidence of faster provider execution. Partial result cards are deliberately still T14–T16 work. Next: T09 bounded AI dispatcher, then T10 discovery/triage overlap.
