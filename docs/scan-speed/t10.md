# T10 — discovery and triage overlap with final reconciliation

Implemented locally August 31, 2026, behind `SCAN_OVERLAP_DISCOVERY_TRIAGE=1`. Default remains off pending real-model semantic and rollout gates. The switch and early-work settings are frozen in the accepted scan configuration, so retries cannot silently change scheduling.

## Scheduling and correctness

`lib/server/discovery-triage-coordinator.ts` receives the existing cumulative `onChunkSucceeded` response. It applies the existing deterministic cleaner at the current wall clock, hashes complete inputs with T09's version function, and submits only new versions into one shared dispatcher. The discovery hook persists its checkpoint but never waits for AI completion. Full batches dispatch immediately; short batches flush after one second (configurable, bounded 0–10 seconds) or when discovery finishes.

Early work is capped at 100 reserved candidate versions per scan, including superseded versions and reservations from earlier attempts (configurable 0–200). This bounds speculative work, not final scan coverage. The same T09 four-request gate covers early work, nested recovery, fallback and simultaneous embedding requests. No search family, page, query limit, actor depth, shortlist budget or relevance rule changes.

`scan-workflow.ts` still cleans the **final** merged corpus and performs its existing global embedding prefilter above 400 candidates. Embedding failure still keeps the full pool. Only after that does it drain early work and retain judgments matching the final candidates' complete input versions. Richer/replaced candidates, changed authors/metrics/lanes and newly eligible timestamps cannot reuse stale early decisions. All missing final judgments then pass through the existing coverage-enforcing triage path before global selection, zero-result audit, enrichment or qualification.

Early judgments use a separate bounded `discoveryTriageCheckpoint`, never the authoritative ID-only checkpoint. The final checkpoint now records exact versions too. A legacy ID-only checkpoint is conservatively re-evaluated when overlap is enabled. Discovery or ownership failure cancels and drains the coordinator before the workflow releases ownership or saves terminal state. An ordinary early AI failure cannot certify final coverage; final reconciliation must recover the missing work or report failure.

## Persistence, progress and measurement

The existing JSONB scan record holds the bounded reservation/judgment ledger. Reload and job retry reuse successful exact versions; no database migration is required. Early progress counts only usable judgments matching the current cleaned input, with the total explicitly unknown until final selection. Concurrent discovery/triage stages use T08's existing display.

`triage.overlap_reconciled` telemetry records reserved versions, final reused judgments and superseded/excluded versions. Successful batch usage is retained, including drained siblings if an early batch failed; provider-level T01 usage remains the source for attempts that failed after consuming tokens. Reserved versions are not an exact HTTP-call or billing count. Extra speculative work must be included in later cost comparisons.

## Verification and limits

Ten new test cases (including nested baseline/overlap comparisons) exercise actual workflow/provider code with deterministic transport stubs: AI starts while a late search is held; the discovery callback returns while AI is still held; richer evidence is resubmitted; a late high-value candidate enters the unchanged eight-review shortlist; a restart reuses 25 saved judgments and submits only the missing candidate; 450-candidate pools and shortlists match sequential execution both with successful embeddings (400 retained) and failed embeddings (450 retained); short batches flush; the current-time timestamp check retains its existing five-minute skew tolerance; reservations remain bounded across retries and invalid numeric settings.

Source-order tests now enforce **final reconciliation → required coverage → enrichment → qualification**, rather than prohibiting useful overlap. Their embedding and quality guards remain intact.

Full suite: **629 total, 627 passed, one known obsolete landing-heading failure, one skipped paid probe**. TypeScript, build, lint and whitespace checks pass; three existing font warnings remain. No live provider benchmark or semantic evaluation was run. Batch regrouping can affect a real model's decisions, so overlap is implemented but not production-enabled. A sample-shaped 2–5 minute gain remains a hypothesis, not a measured result.

Rollback: leave the switch at `0` for new scans; preserve accepted configuration and ledgers for in-flight scans. No production change has been made. Next: T11 coordinated retry budgets and actor reconciliation.
