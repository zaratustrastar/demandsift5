# T12 — compact triage output

Implemented September 1, 2026 in the isolated speed-up branch. Production remains unchanged and `SCAN_COMPACT_TRIAGE` defaults to `0`.

## Outcome

Compact triage keeps the complete candidate evidence, business context, model, output schema, categorical judgments, exact-ID coverage, parser, retry behavior, and generous output-token allowance. It changes only the instruction for two explanatory strings:

- `problem`: one short clause, approximately 160 characters or fewer;
- `reason`: one short clause, approximately 200 characters or fewer.

Those targets are prompt guidance, not lossy truncation. A valid verbose provider response is accepted on the first attempt. DemandSift never cuts returned JSON or reclassifies a record merely because harmless prose exceeds the target.

## Implementation

- `TriageConversationsRequest.compactOutput` is optional; omitted/false retains the legacy prompt.
- `SCAN_COMPACT_TRIAGE` is allowlisted, persisted in the accepted scan configuration, and restored on job retry. A running scan cannot silently switch policy.
- Both sequential triage and T10's discovery/triage coordinator receive the accepted flag.
- Compact requests canonically serialize the same stable business and candidate object. Shared instructions precede variable candidate data, supporting deterministic provider prefix caching where the route offers it.
- The checkpoint hash uses `triage-v2-full-evidence-compact-explanations` in compact mode. Legacy mode keeps the previous `triage-v1-full-evidence` hash exactly, so enabling the experiment cannot reuse a judgment made under another prompt policy and leaving it disabled does not invalidate legacy work.
- No schema `maxLength` was added because both configured routes have not yet demonstrated identical enforcement. This avoids turning harmless verbosity into repair/fallback traffic.

## Verification

- Five compact-output tests pass: configuration freezing, exact checkpoint identity, identical evidence/schema/output allowance, complete labeled ID/decision coverage, acceptance of long valid strings without repair, and real workflow wiring.
- The semantic fixture includes explicit demand, indirect pain, competitor switching, market intelligence, a homonym rejection, and a zero-result audit candidate. The deterministic provider replay returns identical categorical decisions in legacy and compact modes.
- TypeScript and the production build pass.
- Lint has 0 errors and the same three pre-existing font warnings.
- Full suite: 659 tests, 657 passed, 1 opt-in paid probe skipped, and only the known unrelated stale rendered-heading assertion failed.

## Rollout gate

No live output-token or latency reduction is claimed from deterministic stubs. T19 must run the same labeled corpus through both configured provider routes and compare decisions, unresolved coverage, parse/repair frequency, output tokens, latency, and cost. All changed decisions require review, especially indirect-pain, competitor, non-lead market-intelligence, and zero-result cases.

Enable only after that gate with `SCAN_COMPACT_TRIAGE=1`. Rollback is immediate by setting it back to `0`; already accepted scans retain their frozen configuration.
