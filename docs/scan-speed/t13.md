# T13 — controlled AI capacity

Implemented September 1, 2026 in the isolated speed-up branch. The production recommendation remains the existing batch size 25, request concurrency four, and Surplus as primary.

## Outcome

The previous hard-coded 25/four settings are now validated, observable, and frozen with each accepted scan:

- `AI_TRIAGE_BATCH_SIZE`: integer 1–30, default 25;
- `AI_REQUEST_CONCURRENCY`: integer 1–8, default 4.

Invalid settings fail before provider work with `scan_configuration_invalid`; they are never silently clamped. Sequential triage, T10 overlapped triage, nested structured-output repairs, batch bisection, and direct fallback all use the accepted settings.

Providers created through the production factory share one process-wide HTTP gate. Two scans in one worker process therefore cannot each create an independent fan-out. During a mixed rollout, a lower accepted ceiling can tighten the shared gate, but the process does not raise it again until restart. This conservative rule avoids silently exceeding the lower setting. T17 adds the durable cross-worker/queue capacity layer; the process gate alone cannot coordinate separate worker processes.

## Repeatable local experiment

Run:

```sh
node scripts/triage-capacity-replay.mjs
```

The deterministic 276-candidate compatible-provider stub records elapsed time, request count, peak requests, token usage, coverage, retries, throttles, and a digest of every categorical decision. One recorded run produced:

| Batch / concurrency | Requests | Peak | Stub wall time | Coverage | Decision digest |
|---|---:|---:|---:|---|---|
| 25 / 4 | 12 | 4 | 75.6 ms | complete | `f5c949…b043` |
| 25 / 6 | 12 | 6 | 40.0 ms | complete | `f5c949…b043` |
| 20 / 6 | 14 | 6 | 50.5 ms | complete | `f5c949…b043` |

All cases reported 24,840 synthetic input tokens, 12,420 synthetic output tokens, zero unresolved work, retries, or throttles. The test only proves scheduling math and invariants: six permits can turn three idealized waves into two, while a smaller batch added requests and was slower in this shape. It is explicitly not provider-backed latency, rate-limit, cost, or quality evidence.

## Decision

Keep 25/four and Surplus primary. There is insufficient provider-backed evidence to raise concurrency or change routing. Do not infer a production speed-up from the local stub result.

T19 may test concurrency six only after compact-output behavior passes semantic review, using the same provider/model/prompt/corpus and recording 429s, retries, request and queue timing, token usage, cost, coverage, and decision diffs. A direct-OpenAI comparison must use equivalent supported settings; otherwise retain Surplus. Rollback is restoring `AI_TRIAGE_BATCH_SIZE=25` and `AI_REQUEST_CONCURRENCY=4` and restarting workers.
