# T15 — checkpoint and overlap the report tail

Implemented September 1, 2026 in the isolated speed-up branch. Production remains unchanged. The partial-result path stays guarded by `SCAN_PARTIAL_RESULTS=0` until the live dashboard and rollout gates are complete.

## Outcome

Qualified people and relevant conversations are now durably published before report decoration begins. Insight generation and reply drafting then run concurrently against the same immutable, evidence-gated qualification set and through the T13 shared provider request limit.

Lead replies and relevant-non-lead replies share one bounded queue. Lead tasks retain the existing required-result rule; non-lead reply failures remain best effort. A required failure is surfaced only after independent workers and the insight task have drained, so successful siblings are not discarded.

## Reply recovery

Every reply task has a deterministic input version covering:

- the complete approved business profile;
- configured analysis and reply models;
- the enriched conversation and verified thread context;
- the deep qualification and reply angle/instructions;
- a named reply-prompt contract version.

Each complete draft is saved to the reply repository and the scan checkpoint immediately. A same-scan retry reuses only an exact input-version match. Existing cross-scan reuse remains limited to unchanged source content and verified context. Removed tasks prune stale checkpoints and emit partial-result tombstones.

While partial results are enabled, reply states move from `pending` to `ready` or a safe `failed` state. No provider error text is exposed. A failed required reply cannot masquerade as a ready draft, while qualified cards and all earlier successful drafts remain available.

## Behavioral invariants

- Qualification selection, ranking, author deduplication, evidence gates, and review depth are unchanged.
- Insights still fall back to the existing deterministic, sourced result if AI decoration fails.
- Lead replies are processed before optional relevant-conversation replies.
- Output IDs remain stable and retries do not duplicate cards or drafts.
- Final completion still requires all mandatory reply work.

## Verification

- Focused tail tests prove qualified partial persistence precedes decoration, provider windows overlap, and a restart regenerates only the injected failed draft.
- Reply-version tests prove profile, model, conversation/context, qualification, and instruction changes invalidate reuse.
- TypeScript and production build pass.
- Lint has 0 errors and the same three pre-existing font warnings.
- Full suite: 671 tests, 669 passed, 1 opt-in paid probe skipped, and only the known unrelated stale rendered-heading assertion failed.

The measured gain here is architectural overlap and restart recovery. A real-provider latency comparison remains a T19 rollout gate; no paid benchmark was run as part of this local checkpoint.

## Rollback

Revert this checkpoint to restore serial tail execution. Leaving `SCAN_PARTIAL_RESULTS=0` hides intermediate states but does not disable reply checkpoint reuse or tail overlap.
