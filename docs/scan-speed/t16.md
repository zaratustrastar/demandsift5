# T16 — live dashboard with progressively saved results

Implemented September 1, 2026 in the isolated speed-up branch. Production remains unchanged. `SCAN_PARTIAL_RESULTS=0` remains the default until T19 rollout gates are met.

## Outcome

Once a reviewed Reddit run is durably accepted, the user now enters a live dashboard shell instead of a full-screen spinner. The shell uses the approved business profile and compact saved progress while waiting for partial data; it never manufactures a final `ScanResult`.

The live view deliberately separates:

- screened “Conversations being checked,” always labeled qualification pending;
- deep-reviewed potential customers;
- useful relevant conversations, explicitly labeled as not leads;
- grounded replies moving through pending, ready, or safe failed states.

Counts are always labeled “found so far.” Potential customers are counted separately from relevant conversations, and final totals remain exclusive to the completed, coverage-checked report.

## Versioned polling and merge behavior

The existing three-second single-flight status poll remains the clock. The browser reads `runtimeProgress.partialResultsVersion` and calls `GET /api/scans/:id/partial?afterVersion=N` only when that value advances.

The client merge model:

- rejects an older or duplicate top-level version;
- merges each card/reply by stable ID and per-output version;
- treats the bounded server snapshot as authoritative for removals;
- retains the current visual order and appends genuinely new rows;
- announces new rows through a polite live region;
- changes ranking only when the user presses the explicit refresh-order button.

This prevents a polling response from moving the card currently being read. Scroll and native focus remain intact because the live shell and stable keyed rows are not remounted.

## Draft and recovery behavior

Ready reply text is editable in the live shell. Local edits win over later saved snapshots and are applied to the completed dashboard when the final report replaces the live shell. No edit is written to the server or published implicitly.

A transient connection interruption keeps the latest saved cards visible. A retry notice says completed work is saved. If a scan becomes terminally failed but has partial results, it remains in the usable live view with an explicit incomplete-coverage notice instead of discarding the evidence into a generic error screen.

The public partial presenter now includes safe reply-state metadata and per-output versions. Free access bounds previews to three and exposes reply states only for records already visible under the same final-report access rules. Internal fingerprints, hidden record IDs, raw errors, prompts, and checkpoints remain private.

## Responsive user flow

Desktop uses a sticky progress/profile rail beside the live findings. On narrow screens, ready results appear before the long stage history so the first useful output is not buried below progress details. Candidate previews, qualified cards, source links, and editable drafts remain keyboard-native.

## Rollback

Leave `SCAN_PARTIAL_RESULTS=0` to keep new scans on version zero; the live shell then shows truthful progress without partial cards. Reverting this checkpoint restores the earlier scanning screen and leaves final completed-report rendering unchanged.
