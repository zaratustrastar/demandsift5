# T18 handoff — dependable leaving, returning, and completion notice

## Outcome

Every durable primary Market Scan now creates one saved, content-free completion notice at the same checkpoint as final scan completion. The notice has a fixed version, creation time, and nullable read time. It contains no findings, leads, replies, email address, or other report content.

The report displays the unread notice until the user dismisses it. Dismissal calls a workspace-authenticated endpoint and atomically stores `readAt`; repeated dismissal returns the same timestamp rather than creating another event. PostgreSQL row locking and the existing workspace boundary prevent another workspace from reading or acknowledging it. Monitoring-sidecar scans do not create primary-scan alerts.

## Return flow

The existing private `?scan_id=…` URL is now kept canonical after:

- direct or latest-scan restoration;
- Stripe success/cancel cleanup;
- Reddit OAuth callback cleanup;
- report refresh and explicit monitoring-result navigation.

Starting a genuinely new scan or choosing “New scan” clears the old ID until the newly created scan is durable. The ID is only a locator: every API read still requires the owning anonymous workspace cookie or the signed-in account. Copy explains the real portability boundary: anonymous restoration works in the same browser; another browser/device requires the same signed-in account.

The existing `/api/scans/latest` behavior remains the recent-state fallback when no explicit ID is present, including running, retrying, failed, and completed primary scans. Daily monitoring child scans remain excluded from that default lookup.

## Email decision

No production email is promised or exposed. The repository contains an email interface and a development console sink, but no production adapter is registered and the console provider is explicitly disabled in production. Adding an opt-in email preference/outbox without a callable production delivery adapter would create a false promise, so it remains an external integration gate.

When a production adapter is chosen later, delivery should use the verified signed-in account email only, an outbox keyed by scan ID plus `scan-complete-v1`, and a link with no report content in the message. Delivery must remain outside the scan critical path, and failures must never fail or delay a completed scan.

## Verification

- Workflow tests verify a primary completion creates one minimal unread notice and a monitoring scan creates none.
- Local PostgreSQL tests verify read state survives reload, is idempotent, and is workspace-fenced.
- Source/access tests verify the acknowledgement route requires a workspace, uses private/no-store responses, and the stable URL is retained.
- Existing provider tests verify production refuses the console email sink and refuses an unregistered provider.
- Full regression: 691 tests, 689 passed, one opt-in paid probe skipped, and only the pre-existing rendered-heading expectation failed.

## Rollback

The completion notice is an additive optional JSON field on `runtime_scans.record`; no destructive migration is required. Removing the banner/acknowledgement route leaves scan reports and saved URLs usable. Older scans with no notice continue to render normally.
